## Общая оценка

Для своего размера (~1000 строк) архитектура хорошая: один движок (`Compressor`), одна очередь
(`JobStore`), тонкий UI, CLI на том же движке, никаких Swift-зависимостей, тяжёлую работу
делают проверенные внешние инструменты. Последовательная очередь и «оригинал в Корзину» —
правильные решения.

Слабое место — граница между приложением и внешними процессами: временные файлы, отмена,
замена файла на месте, выход из приложения. Почти все серьёзные находки оттуда.

## Блок 1. Надёжность (риск для файлов пользователя)

### 1. Замена файла не атомарна
`Compressor.swift:133-134` — сначала оригинал уходит в Корзину, потом результат переезжает
из `$TMPDIR`. Если перенос упал (диск полон, права, внешний диск) — оригинал в Корзине,
на его месте пусто. Для файлов на внешнем диске «перенос» — это копирование гигабайтов
с другого тома, окно для сбоя большое.

**Фикс:** временные файлы создавать на том же томе, что и оригинал
(`FileManager.url(for: .itemReplacementDirectory, in: .userDomainMask, appropriateFor:)`).
Порядок: результат уже лежит на том же томе → оригинал в Корзину → мгновенный rename.
Если что-то упало до Корзины — оригинал не тронут.

**Тест первым:** `finalize` с несуществующим `produced` бросает ошибку, а оригинал остаётся
на месте (сейчас он уезжает в Корзину).

### 2. Отмена не всегда отменяет
`JobStore.swift:117-121` убивает только процессы, запущенные в этот момент. Задача при этом
продолжает жить:
- fast path JPEG (`Compressor.swift:194`): убитый mozjpeg ловится через `try?`, и код
  проваливается в общий путь — запускает cjpeg заново и **заменяет файл**, хотя строку удалили;
- отмена между двумя процессами (ImageIO → cwebp и т.п.) ничего не убивает;
- `finalize` выполняется даже после отмены.

В project.md написано «оригинал при отмене не тронут» — сейчас это не гарантировано.

**Фикс:** флаг отмены на задачу; проверять перед каждым запуском процесса и перед `finalize`;
при отмене удалять временные файлы.

### 3. Удаление строки убивает установку brew
`cancelCurrent()` (`Compressor.swift:402`) завершает **все** отслеживаемые процессы, включая
`brew install`, запущенный через тот же `Compressor.run` (`JobStore.swift:196`).

**Фикс:** отслеживать процессы по задаче, brew — отдельно и без отмены.

### 4. Бесконечный цикл установки brew
`JobStore.swift:210`: если `brew install` не удался (нет сети, ошибка формулы), инструмент
остаётся в `missingTools`, и `finishInstall` сразу запускает установку заново — навсегда.

**Фикс:** смотреть код выхода; при неудаче показывать ошибку в баннере и не повторять,
пока пользователь не нажмёт кнопку снова.

### 5. Возможный краш по SIGPIPE
`Compressor.swift:298` пишет PPM в stdin cjpeg. Если cjpeg к этому моменту умер (отмена,
ошибка) — запись в закрытый pipe шлёт приложению SIGPIPE, и оно падает.

**Фикс:** писать PPM во временный файл и передавать cjpeg путь. Заодно решает п. 13 (память).

### 6. Выход посреди работы оставляет процессы-сироты
`Main.swift:64` — закрыл окно → приложение завершилось, а запущенный ffmpeg продолжает
кодировать десятки минут в никуда (дочерние процессы не убиваются вместе с родителем).

**Фикс:** `applicationShouldTerminate` — если идёт работа, отменить задачу, убить процессы,
почистить временные файлы. (Вопрос: спрашивать подтверждение или молча отменять?)

### 7. Утечки временных файлов
- при ошибке/отмене pdf и video не удаляют свой tmp (`Compressor.swift:348, 367`) —
  недописанное видео может весить гигабайты;
- LibreOffice каждый раз оставляет папку с профилем (десятки МБ, `Compressor.swift:373`);
- если `finalize` упал — результат остаётся в tmp.

**Фикс:** одна временная папка на задачу, удаляется в `defer` при любом исходе.
Делается вместе с п. 1.

### 8. Re-run может взять чужой файл из Корзины
`JobStore.swift:101, 155` — путь оригинала в Корзине хранится просто строкой. Если Корзину
очистили, а потом туда попал другой файл с тем же именем, re-run пережмёт **чужой** файл
и поставит его на место пользовательского. Редко, но это тихая порча данных.

**Фикс:** вместе с путём запоминать идентичность файла (`fileResourceIdentifierKey`,
либо размер + дата изменения) и сверять перед использованием.

## Блок 2. Качество результата

### 9. Вместо mozjpeg работает обычный libjpeg-turbo
mozjpeg в Homebrew — keg-only: ставится в `/opt/homebrew/opt/mozjpeg/bin` и **не** линкуется
в `/opt/homebrew/bin`. `Tools.path` (`Compressor.swift:59`) ищет только в `bin`, поэтому:
- на этой машине `/opt/homebrew/bin/cjpeg` → jpeg-turbo 3.2.0 (пришёл зависимостью);
- таблица качества подобрана под mozjpeg, а работает обычный энкодер — файлы крупнее;
- даже `brew install mozjpeg` ситуацию не меняет.

**Фикс:** искать сначала в `/opt/homebrew/opt/mozjpeg/bin` и `/usr/local/opt/mozjpeg/bin`.
**Тест первым:** `Tools.path` находит инструмент в keg-каталоге (каталоги передаются параметром).

### 10. JPEG теряет метаданные и цветовой профиль
Путь `djpeg | cjpeg` и `cjpegEncode` выкидывают EXIF (дата съёмки, камера, GPS) и ICC-профиль.
Фото в Display P3 после сжатия выглядят тусклее, а фотобиблиотеки теряют дату съёмки.

**Фикс (нативно, без зависимостей):** после cjpeg скопировать метаданные исходника через
`CGImageDestinationCopyImageSource` — без перекодирования. ICC — флагом `cjpeg -icc`.
(Вопрос: сохранять ли GPS или вырезать ради приватности?)

### 11. Видео — проверить
- `-q:v` у `hevc_videotoolbox` работает только на Apple Silicon; на Intel ffmpeg упадёт.
  (Вопрос: нужна ли поддержка Intel?)
- аудио всегда перекодируется в AAC 160k — если оно уже AAC, лучше `-c:a copy`;
- дополнительные аудиодорожки и субтитры теряются;
- проверить HDR-видео с iPhone (10 бит, HLG) — не потеряется ли HDR.

## Блок 3. Производительность

### 12. Блокирующие ожидания в пуле Swift Concurrency
`Task.detached` + `waitUntilExit()` (`JobStore.swift:147`, `Compressor.swift:425`) держат поток
кооперативного пула минутами. Сейчас терпимо (одна задача + brew), но любая параллелизация
в это упрётся.

**Фикс:** `terminationHandler` + `withCheckedContinuation`. Заодно даёт естественную отмену
для п. 2.

### 13. Пиковая память в `cjpegEncode`
`Compressor.swift:267-287`: RGBA-буфер + RGB-буфер + копия при `append` ≈ 9–10 байт на пиксель
поверх уже декодированной картинки. Фото на 50 Мп → ~0,5 ГБ. Решается п. 5 (запись в файл).

### 14. Параллельная очередь для лёгких форматов
Сейчас строго по одному. Картинки и PDF можно гнать по 2–4 параллельно, видео — по одному.
Делать только после п. 12 и только если пачки картинок реально медленные.

### 15. Мелочи UI
- `DisableHorizontalBounce.updateNSView` (`ContentView.swift:160`) обходит всё дерево вью
  при каждом обновлении таблицы — достаточно одного раза;
- `NSWorkspace.icon(forFile:)` вызывается в `body` для строк без миниатюры.

## Блок 4. Архитектура

### 16. Настройки — явный снимок вместо чтения UserDefaults изнутри движка
Сейчас `Compressor` читает настройки прямо посреди задачи (`Compressor.swift:165, 336, 354`),
а `JobStore` сравнивает их склейкой строк (`JobStore.swift:50`).

**Фикс:** `struct Settings: Equatable` — читается один раз при запуске задачи и передаётся
в `compress`. Плюсы: настройки не меняются посреди задачи; движок тестируется без
UserDefaults; «настройки изменились» — просто `!=`.

### 17. Тесты
Сейчас покрыты только `finalize` и подписи уровней. После п. 16 — тесты на выбор пути
(fast path / общий), на аргументы инструментов и интеграционные тесты с реальными
инструментами (пропускаются, если инструмента нет).

## Решения по вопросам

2. EXIF сохранять целиком, включая GPS; цветовой профиль обязателен.
3. Intel-маки пока не поддерживаем.
